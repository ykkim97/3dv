# 순차 기능 개발 기록

사용자 요청에 따라 아래 순서를 유지한다. 매뉴얼 작업으로 잠시 전환했으며, 이후 기능 개발을 재개할 때 2단계부터 이어간다. 이 기록은 자동 작업 실행이나 완료를 의미하지 않는다.

1. **완료: 시설 속성 관리** — 이름, 설비 번호, 운전 상태, 출력·수요·용량; JSON 저장, 중복 검사, 복제, 실행 취소. 속성은 아직 공급 계산에 반영되지 않는다.
2. **다음: 연결망 기반 공급 계산** — 전력·수도 연결선을 그래프로 해석하고 공급원, 중계, 소비시설을 구분한다. 방향·운전 상태·용량·수요 및 미입력 값의 처리 정책을 정하고 기존 반경 방식과 파일 호환성을 유지한다. ESS 충방전은 시간 모델 없이 실제 시뮬레이션으로 표현하지 않는다.
3. 고장·복구 시나리오 — 시설/연결 정지와 복구, 영향 범위 비교, 원래 상태 복원.
4. 운영 대시보드 — 공급·수요·부족량·상태·경고를 집계하고 해당 시설로 이동.
5. 연결선 경유점 편집 — 경로 제어 및 시설 이동 시 연결 유지.
6. 성능 모니터·품질 설정 — 프레임, 렌더링 부하, 품질 옵션과 대형 씬 검증.
7. 자동 저장·복구·프로젝트 목록 — 저장 실패 및 복구 흐름 포함.
8. 복합 시설 프리셋 — 발전단지, 변전소, 산업단지 등을 묶어 배치.
9. 발표 모드·카메라 투어 — 편집 UI 숨김과 저장 시점 순회.
10. 외부 데이터 연결 — CSV/JSON부터 시작하고 이후 실시간 데이터 연결.

공통 원칙: 시설 수가 늘어도 프레임 부하를 줄이도록 변경 시 계산, 렌더링 캐시, 필요 시 Worker를 사용한다. 실제 FPS는 측정 없이 개선 수치를 주장하지 않는다. 각 단계는 기존 도시 JSON과 실행 취소를 검증한다.

## 매뉴얼과 향후 JavaScript API

- 매뉴얼: `src/features/city/manual/`. 실제 프리셋 카탈로그와 흐름 효과 목록을 사용한다.
- 향후 별도 요청: 비개발자도 쉽게 사용할 JavaScript 편의 API. 현재 도시 편집기에는 공개 편의 API가 없으므로, 매뉴얼에서는 준비 중으로 표시하고 가상의 함수를 사용 가능한 것으로 소개하지 않는다.
- API를 구현하면 문법, 입력값, 반환값, 오류, 실행 취소, 복사 가능한 예제를 매뉴얼에 함께 추가한다.
